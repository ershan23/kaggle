# Playground Series S6E8：智能手机成瘾预测

## 1. 比赛规则与目标

| 项目 | 说明 |
|------|------|
| 竞赛 | [Predicting Smartphone Addiction](https://www.kaggle.com/competitions/playground-series-s6e8)（Playground Series - Season 6 Episode 8） |
| 任务 | 二分类：预测用户是否存在智能手机成瘾（`addicted_label` ∈ {0,1}） |
| 评估 | **ROC-AUC**（预测概率与真实标签之间） |
| 提交格式 | `id, addicted_label`，其中 `addicted_label` 为 **概率**（非 0/1） |

数据来源为合成数据（基于公开「智能手机使用与成瘾」类数据集生成），特征为行为与生活方式指标。

## 2. 数据概况

| 数据集 | 行数 | 列数 |
|--------|------|------|
| `train.csv` | 691,369 | 14（含目标） |
| `test.csv` | 296,302 | 13 |
| `sample_submission.csv` | 296,302 | 2 |

**目标分布（训练集）**

- 正类（成瘾=1）：490,474（约 **70.94%**）
- 负类（成瘾=0）：200,895（约 **29.06%**）
- 类别不平衡明显，但 AUC 对阈值阈值仍友好；建模时直接输出概率即可。

**特征列表**

| 类型 | 字段 |
|------|------|
| 数值 | `age`, `daily_screen_time_hours`, `social_media_hours`, `gaming_hours`, `work_study_hours`, `sleep_hours`, `notifications_per_day`, `app_opens_per_day`, `weekend_screen_time` |
| 类别 | `gender`, `stress_level`, `academic_work_impact` |
| 目标 | `addicted_label` |

## 3. EDA 要点

### 3.1 缺失值

训练集与测试集均有系统性缺失，缺失率约 **4%–20%**：

- 较高：`social_media_hours`、`gaming_hours`、`weekend_screen_time`、`daily_screen_time_hours`
- 中等：`app_opens_per_day`、`notifications_per_day`、`stress_level` 等

缺失本身对目标均值影响不大（缺失/非缺失目标率接近），但对树模型仍建议保留 **缺失指示特征**。

### 3.2 与目标的相关性（数值）

| 特征 | 与目标相关系数（约） |
|------|----------------------|
| `daily_screen_time_hours` | **0.61** |
| `weekend_screen_time` | **0.59** |
| `social_media_hours` | **0.53** |
| `work_study_hours` | 0.25 |
| `gaming_hours` | 0.21 |
| 其余 | 较弱 |

屏幕时长相关特征呈极强单调关系：日均屏幕 >10h 的成瘾率接近 **99.9%**，低屏幕时长段成瘾率约 **29%**。

### 3.3 类别特征

`gender` / `stress_level` / `academic_work_impact` 各水平目标率差异很小（约 0.70–0.72），单独区分力弱，适合作为辅助特征由树模型组合使用。

## 4. 特征工程

实现见 `src/features.py`，主要构造：

1. **缺失指示**：各列 `_isna` + `missing_count`
2. **时长结构**：娱乐时长、社交/游戏/工作占比、周末相对工作日比、周末超额
3. **睡眠与屏幕**：睡眠缺口、屏睡比
4. **互动强度**：通知/打开比、总互动、单次打开屏幕时长
5. **阈值指示**：重度屏幕 / 重度周末 / 重度社交
6. **序数编码**：压力等级、学业/工作影响
7. **交互项**：屏幕×社交、屏幕×周末、压力×屏幕等

树模型原生支持缺失，数值缺失不强制填补；类别在 LGBM/XGB 中转为 `category`，CatBoost 使用字符串类别。

## 5. Baseline

脚本：`src/baseline.py`

| 模型 | OOF / Fold AUC |
|------|----------------|
| 仅 3 个强特征 + LogisticRegression | ≈ 0.911 |
| 全数值特征 + LogisticRegression | ≈ 0.926 |
| LightGBM（单折快速验证） | ≈ **0.962** |

结论：非线性树模型明显优于线性模型；后续以 GBDT 族为主。

## 6. 正式建模与验证

脚本：`src/train_pipeline.py`

- **验证**：`StratifiedKFold`，5 折，`random_state=42`
- **模型**：LightGBM / XGBoost / CatBoost（early stopping）
- **融合**：基于 OOF 的凸组合权重网格搜索（步长 0.1）
- **输出**：
  - `submission.csv`（融合概率）
  - `output/submission_{lgbm,xgb,cat}.csv`
  - `output/oof_predictions.csv`
  - `output/cv_results.json`

本地 CV 指标（5 折 StratifiedKFold，seed=42）：

| 模型 | OOF AUC | Fold 均值 ± 标准差 |
|------|---------|-------------------|
| LightGBM | 0.96380 | 0.96380 ± 0.00052 |
| XGBoost | **0.96451** | 0.96451 ± 0.00050 |
| CatBoost | 0.96337 | 0.96337 ± 0.00051 |
| **Blend**（0.2 / 0.6 / 0.2） | **0.96471** | LGBM:XGB:CAT = 0.2:0.6:0.2 |

相对 Baseline：Logistic ≈ 0.926 → 融合 **+0.039** AUC。
